# Дизайн-система Aurora

Дата: 2026-09-08
Статус: согласован, готов к передаче дизайнеру

## 1. Зачем

Приложение мониторинга автопарка переезжает на Flutter, чтобы Android и iOS
выпускались одновременно. Вместе с переездом нужен редизайн и внятная
white-label архитектура: Aurora — базовый бренд, поверх него строятся МТС,
Irissoft и следующие.

Документ описывает дизайн-систему: токены, палитру, типографику, форму,
поведение и состав компонентов. Он адресован дизайнеру, который будет рисовать
Figma-библиотеку, и разработчику, который будет её кодировать.

### Что не входит

- Редизайн конкретных экранов — отдельный цикл после Figma-библиотеки.
- План миграции Kotlin → Flutter — отдельный цикл.
- Информационная архитектура и навигация — не меняются этим документом.

## 2. Исходное состояние

| Что | Сейчас |
|---|---|
| UI | 76 XML-layout, View-система, Compose нет |
| Код | ~23 400 строк Kotlin, логика внутри фрагментов |
| Бренды | три source set: `aurora`, `irissoft`, `mts` |
| Дублирование | `MapFragment` (~1 480 строк) скопирован в каждый флейвор; между `aurora` и `mts` разница 29 строк diff |
| Реальные различия брендов | base URL, дефолтная локаль, набор цветов |
| Тёмная тема | отсутствует: `values-night/` содержит один неиспользуемый overlay |
| Токены | нет; в layout стоят `@color/colorWhite`, `@color/colorBlack` напрямую |
| Иконки | 23 из 206 drawable имеют цвет в имени файла (`ic_map_blue`, `ic_close_white`) |
| Вордмарк | `branded_image.xml` залит `#FF000000` без возможности тонирования |
| Языки | 14, включая арабский (RTL) и греческий |

Ключевая находка: палитра логотипа и палитра приложения не совпадают. В
`aurora_logo_240.xml` живут `#0081C9`, `#004F9F`, `#1E2668`, `#F4E84B`, а
интерфейс покрашен в `#3493F8` — цвет, которого в знаке нет.

## 3. Принятые решения

| Решение | Выбор | Почему |
|---|---|---|
| Платформа | Flutter | Переиспользуемой логики в текущем коде почти нет (`TrackerViewModel` сросся с `MapLibreMap`, `GoogleMap`, `Context`); приложение упирается в четыре нативные интеграции — карта, плеер, графики, PDF — и на Flutter у каждой одна поддерживаемая реализация вместо двух собственных `expect/actual` |
| Где живёт индивидуальность | В форме и поведении, не в цвете | Бренды заменяют палитру целиком (МТС уже ушёл в серый + красный). Характер, привязанный к цвету, не пережил бы перекраску |
| Хроматика интерфейса | Обвязка нейтральная, цвет только у данных | Приложение картоцентричное: чем тише хром, тем читаемее карта и отчёты |
| Нейтрали | Подкрашены в оттенок бренда (`neutralHue`) | Одна переменная отличает холодную Aurora от тёплого МТС; стоит ноль усилий, даёт всю разницу настроения |
| Брендовый цвет | По мотивам логотипа: `#0066B8` / `#3E9BE0` | У знака уже есть характер, приложение им не пользовалось. Буквально этих оттенков в знаке нет: `#0066B8` лежит между `#0081C9` и `#004F9F` логотипа, шкала подобрана вокруг него |
| Жёлтый `#F4E84B` | Не используется | Рассматривался как маркер фокуса, отклонён |
| Форма | Панельная: радиусы 8/12/16, строка 52, **теней нет** | Плотность инструмента при современном виде; разделение тоном работает одинаково в обеих темах, дёшево на длинных списках и переживает перекраску |
| Шрифт | Inter везде, обе платформы | Единый вид на iOS и Android — ради этого и затевалась кроссплатформа |
| Моноширинный | Нет | Выравнивание колонок даёт `tabular-nums` внутри Inter; отдельная гарнитура была излишеством |
| Статусные цвета | Общие для всех брендов | Означают состояние объекта, а не клиента |

## 4. Архитектура токенов

Три слоя. Компонент видит только средний.

### 4.1 Primitive

Сырые значения без смысла: `neutral.400`, `brand.600`, `space.4`, `radius.md`.

**Цветовые шкалы рисует дизайнер, а не генератор.** Ранняя редакция этого
документа обещала выводить `neutral` из `neutralHue` и `brand` из `brand.seed`;
на практике все 48 оттенков подобраны вручную, и это правильно: сгенерированная
шкала всё равно оказалась бы черновиком, поверх которого дизайнер прошёлся бы
своей рукой, а самые узкие места (`text.secondary` на `surface.chrome` у МТС —
запас 0.04 над AA, §12) подбираются глазом и калькулятором контраста, а не
кривой светлоты.

`neutralHue` и `seed` остаются в файле бренда, но они **описывают замысел, а не
производят шкалу**: 232° и `#0066B8` у Aurora, 28° и `#E30611` у МТС. Чтобы они
не превратились в мёртвые поля, `tools/parity.js` требует, чтобы `seed`
буквально встречался среди ступеней собственной шкалы `brand`. Ступень при этом
не фиксирована: у Aurora seed стоит на 600, у МТС — на 500, потому что
фирменный красный МТС это и есть 500, а 600 у них затемнённый вариант, который
несёт контраст.

Остальные примитивы — отступы, радиусы, высоты строк, типографика, движение,
статусные цвета, палитра геозон — общие для всех брендов и меняются только
вместе для всех.

### 4.2 Semantic

Привязка к роли и к теме. Только этот слой имеет светлый и тёмный вариант, и
только его видят компоненты.

### 4.3 Component

Точечно, где нужна отдельная ручка: `listRow.height`, `chip.radius`,
`button.primary.bg`. Не заводится «на всякий случай».

### 4.4 Правило

**Компонент никогда не обращается к primitive напрямую.** Встретившийся в
виджете `neutral900` — это баг. Именно так тёмная тема ломается в текущем
приложении: `@color/colorWhite` стоит прямо в layout, и никакой `values-night`
его не переопределит.

### 5.3 Статусы

Фиксированные, одинаковые у всех брендов. Пять состояний по числу реальных
состояний объекта.

| Роль | Светлая | Тёмная |
|---|---|---|
| `status.moving` | `#12A150` | `#2BD47A` |
| `status.parked` | `#6E7480` | `#9CA2AE` |
| `status.warning` | `#B7791F` | `#F0B429` |
| `status.alarm` | `#C7301F` | `#F0554F` |
| `status.offline` | `#8D9096` | `#606677` |

**`status.offline` переехал.** Исходные `#C9CDD6` / `#40444F` давали на
`surface.content` контраст 1.59 в светлой теме и 1.87–1.91 в тёмной: точка
«нет связи» была практически не видна ни там, ни там. «Нет связи» — это
состояние объекта, а не отсутствие состояния, поэтому на неё распространяется
тот же порог 3.0, что и на остальные четыре. Новые значения дают 3.20 в
светлой и 3.18–3.24 в тёмной — порог взят, но не перекрыт: `offline` остаётся
самым низкоконтрастным из пяти (следующий — `moving`, 3.37 в светлой; `alarm`,
5.31 в тёмной) и потому по-прежнему читается как приглушённое состояние.
Оттенок сохранён — это тот же холодный серый, только сдвинутый по светлоте.
Рядом с `status.parked` (`#6E7480` / `#9CA2AE`) он различим: 1.47 в светлой
и 2.24 в тёмной. Все пять порогов держит `CONTRAST_PAIRS` в
`design-system/tools/validate.js`.

Текущий `colors.xml` содержит девять статусных цветов с дублями:
`colorGreen` и `colorCarSelected` — оба `#0ad35b`. Схлопывается до пяти.

**Отдельно:** в МТС-флейворе `colorCheckBox` = `#e30611`, то есть фирменный
красный используется как цвет активного чекбокса. После перехода на систему
фирменный цвет и «тревога» разводятся: `action.primary` берётся из
`brand.600`, `status.alarm` — из фиксированной шкалы.

| Токен | Светлая | Тёмная |
|---|---|---|
| `surface.content` | `neutral.0` | `neutral.1000` |
| `surface.chrome` | `neutral.50` | `neutral.900` |
| `surface.selected` | `neutral.0` смешан с `brand.600` 4% | `neutral.850` |
| `surface.overlay` | `neutral.0` | `neutral.900` |
| `surface.scrim` | `neutral.1000` с альфой 40% | `neutral.1000` с альфой 60% |
| `border.hairline` | `neutral.100` | `neutral.850` |
| `border.strong` | `neutral.200` | `neutral.800` |
| `text.primary` | `neutral.950` | `neutral.50` |
| `text.secondary` | `neutral.500` | `neutral.400` |
| `text.disabled` | `neutral.300` | `neutral.700` |
| `text.onBrand` | `neutral.0` | `neutral.1000` |
| `action.primary` | `brand.600` | `brand.400` |
| `action.pressed` | `brand.700` | `brand.500` |
| `action.subtle` | `brand.50` | `brand.900` |
| `focus.indicator` | `action.primary` | `action.primary` |

`surface.selected` подмешивается к `surface.content`, а не к хрому: строка
списка лежит на `content`, и выделенная строка — это та же строка с подсветкой.
Замес от `neutral.50` делал выбранную строку темнее той, которую она
подсвечивает, и уводил `text.secondary` на ней под AA в светлой теме МТС
(4.23 при пороге 4.5). После пересадки на `neutral.0`: Aurora `#F5F9FC` — 4.90,
МТС `#FDF5F5` — 4.57.

В тёмной теме порядок поверхностей инвертируется: `surface.content` в светлой —
самый светлый, в тёмной — самый тёмный. Строки списка лежат на `content`,
заголовки секций и итоги — на `chrome`.

`surface.scrim` — затемнение под диалогом, шторкой и выдвижной панелью.
Светлая альфа 40% совпадает с сегодняшним `black_overlay` (`#66000000`),
только тон взят из нейтральной шкалы бренда, а не чистый чёрный. Тёмная 60%
поставлена по рассуждению: над тёмным контентом 40% почти не читается как
затемнение. Точное значение — вопрос к дизайнеру (§12). Без этого токена
Flutter подставлял бы своё `black54`, и затемнение оставалось бы единственным
цветом на экране не из системы.

### 5.5 Карта

| Токен | Идентификатор в JSON | Значение |
|---|---|---|
| `map.track.default` | `map.trackDefault` | `action.primary` |
| `map.track.speeding` | `map.trackSpeeding` | `status.alarm` |
| `map.track.selected` | `map.trackSelected` | `text.primary` |
| `map.marker.selected` | `map.markerFill` / `map.markerStroke` | заливка `surface.content`, обводка `text.primary` 2 dp |
| `map.cluster` | `map.clusterFill` / `map.clusterText` | заливка `surface.overlay`, текст `text.primary` |

**Это именно алиасы, а не совпадающие значения.** В семантическом файле они
записаны как `{semantic.action.primary}` и разворачиваются по ссылке. То же
относится к `focus.indicator` из §5.4. Разница не косметическая: при плоской
записи сдвиг `action.primary` не доезжал бы ни до фокусного кольца, ни до
трека — и все проверки оставались бы зелёными.

Цвета геозон (`aqua`, `blue`, `gray`, `green`, `orange`, `purple`, `red`,
`yellow`) — **пользовательские данные, а не оформление**: их назначает
оператор. Поэтому они, как и статусы, общие для всех брендов и лежат в
`tokens/primitive/geofence.json`; семантический слой добавляет к ним только
альфу, потому что альфа зависит от темы.

| Имя | Тон | Светлая | Тёмная |
|---|---|---|---|
| `aqua` | `#00FFFF` | 25% | 35% |
| `blue` | `#0000FF` | 25% | 35% |
| `gray` | `#7F7F7F` | 25% | 35% |
| `green` | `#00FF00` | 25% | 35% |
| `orange` | `#FF9200` | 25% | 35% |
| `purple` | `#932092` | 25% | 35% |
| `red` | `#FF0000` | 25% | 35% |
| `yellow` | `#FFFF00` | 25% | 35% |

Тона перенесены один в один из `app/src/main/res/values/colors.xml` — их
присылает сервер по имени, поэтому перекрашивать их нельзя. Светлая альфа
25% — тоже та, что в приложении сегодня (`#40......`). Тёмная 35% поставлена
потому, что тёмная подложка карты сама малоконтрастна и 25% заливки на ней
читаются как шум, а не как область; точное значение — вопрос к дизайнеру на
реальных тайлах (§12).

## 6. Типографика

Inter, все начертания. Арабский — Noto Sans Arabic (у Inter арабского нет);
в Dart он стоит `fontFamilyFallback` у каждой роли и у `ThemeData`, файлы
шрифтов в пакет пока не положены (§11).

| Роль | Размер / интерлиньяж | Вес | Трекинг | Где |
|---|---|---|---|---|
| `display` | 28 / 34 | 600 | −1.5% | заголовок экрана |
| `title` | 20 / 26 | 600 | −1% | заголовок секции, диалога |
| `section` | 15 / 20 | 600 | 0 | подзаголовок внутри контента |
| `body` | 15 / 22 | 400 | 0 | основной текст |
| `label` | 13 / 18 | 550 | 0 | строка списка, кнопка |
| `caption` | 11 / 15 | 400 | 0 | вторичное, единицы измерения |
| `overline` | 9 / 12 | 700 | +8%, uppercase | липкий заголовок даты |
| `number.lg` | 20 / 24 | 600 | `tnum` | скорость в HUD |
| `number.md` | 14 / 18 | 600 | `tnum` | число в строке отчёта |
| `number.sm` | 11 / 14 | 600 | `tnum` | время, координаты |

Числовые роли — тот же Inter с включёнными табличными цифрами
(`font-variant-numeric: tabular-nums`), а не отдельная гарнитура.

**Правило:** любое число в колонке набирается числовой ролью. Проприетарные
`LowercasedTextView` (46 использований) и `DistanceTextView` (14) перестают
быть виджетами — это правила форматирования, им место в типографике и
форматтерах.

## 7. Пространство и форма

**Отступы**, шаг 4: `2, 4, 8, 12, 16, 20, 24, 32, 40, 48`.
Горизонтальный отступ экрана — 16, внутренний отступ строки — 14.

**Радиусы:** `4` (вложенное), `8` (чип, поле ввода, кнопка), `12` (панель),
`16` (экран, шторка), `pill` (аватар, счётчик).

**Высоты строк:** `40` компактная, `52` основная, `64` двухстрочная.
Минимальная зона нажатия — `44` независимо от визуального размера.

**Разделение поверхностей — тоном и волосяной границей. Теней нет.**
`elevation` в системе не существует как понятие: нет `boxShadow`, нет
`Material.elevation`, нет ripple с тенью. Это осознанный характерный приём —
он одинаково работает в обеих темах (в тёмной тени всё равно не читаются),
дёшев на длинных списках и целиком переживает перекраску.

**Выделение активного:** вертикальная полоса 2 dp слева цветом
`action.primary` плюс `surface.selected`. Один выделитель на экране — не
подсвечиваем одновременно фоном, полосой и рамкой.

## 8. Поведение

| Токен | Значение |
|---|---|
| `duration.fast` | 120 мс |
| `duration.base` | 200 мс |
| `duration.slow` | 320 мс |
| `duration.dataInterp` | 500 мс |
| `curve.enter` | `easeOutCubic` |
| `curve.exit` | `easeInCubic` |

**Правила:**

1. **Движение объясняет, откуда взялся экран.** Панель выезжает с той
   стороны, где живёт: детали трека — справа, фильтр — снизу, детали
   уведомления — из строки списка. `duration.base`, `curve.enter`.
2. **Данные не мигают.** Объект на карте интерполирует позицию за
   `duration.dataInterp`, а не телепортируется. Числа в HUD меняются коротким
   кроссфейдом. Мигающий интерфейс читается как глючащий.
3. **Скелетоны вместо спиннеров** там, где форма результата известна заранее
   (списки, отчёты). Спиннер остаётся для построения трека и загрузки видео.
4. **RTL с первого дня.** Арабский уже в проекте. Все отступы логические
   (`start`/`end`). Карта, графики и числа не зеркалятся; стрелки направления
   движения — зеркалятся.

на мобильном, особенно при выборе из сотни объектов.

## 10. Брендирование

Бренд — один файл конфигурации:

```jsonc
{
  // Полные шкалы — 14 и 10 ступеней, здесь сокращено.
  "id": "aurora",
  "appName": "Aurora",
  "logo": "aurora.svg",
  "wordmark": "aurora-wordmark.svg",
  "baseUrl": "https://api.aurora-soft.by/",
  "defaultLocale": "en",
  "neutralHue": 232,
  "seed": "#0066B8",
  "color": {
    "neutral": { "0": "#FFFFFF", "50": "#F4F6FA", "100": "#EFF1F6" },
    "brand":   { "50": "#E8F2FB", "100": "#CBE3F6" }
  }
}
```

Меняются ровно четыре визуальные вещи: шкала `neutral`, шкала `brand`, `logo`
и `wordmark`. Не меняется ничего из: радиусов, отступов, высот строк, шрифта,
статусных цветов, палитры геозон, правил движения, отсутствия теней —
`tools/parity.js` это стережёт и падает на любом лишнем ключе в файле бренда.

`logo` и `wordmark` лежат в `design-system/assets/brand/`, и `parity.js`
требует, чтобы файлы существовали: бренд без знака сборку не проходит. У
Aurora это `aurora.svg` и `aurora-wordmark.svg`, сконвертированные из
`aurora_logo_240.xml` и `branded_image.xml` текущего приложения; вордмарк
залит `currentColor` (§9.3) и красится токеном `text.*`. У МТС векторного
исходника в проекте нет, поэтому лежат `mts.png` и `mts-wordmark.png` из
сплэша, 240 px и 180 px; вектор — вопрос к дизайнеру (§12).

Обе шкалы перекрашиваются на месте: набор ступеней (включая нестандартную
`850` в `neutral`) обязан совпасть с эталонным, иначе сборка не пройдёт.
Шкалы подбирает дизайнер (§4.1); `seed` и `neutralHue` записывают, откуда
шкала растёт, и `seed` обязан быть одной из ступеней `brand`.

Это заменяет 4 900 строк дублированного Kotlin в трёх source set, которые
существуют сейчас ради base URL, дефолтной локали и набора цветов.

**Новый бренд подключается добавлением файла и ассетов, без строк кода.**

## 11. Поставка

**Источник истины — JSON токенов в репозитории**, в собственном формате:
ссылки `{ref}`, функции `mix()` и `alpha()`, по два значения на тему. Это не
W3C Design Tokens и не Style Dictionary; переход на стандартный формат
возможен, но пока потребителей два, Dart и Figma, его никто не требует. Из
JSON генерируются:

- Dart: `AuroraTheme extends ThemeExtension<AuroraTheme>` с полями
  семантического слоя; бренд выбирается флейвором, светлая и тёмная — две
  инстанции того же класса. `auroraThemeData()` собирает `ThemeData`:
  обнуляет тени и прокидывает токены в `ColorScheme` поимённо, потому что
  незаданные поля схемы не пустые, а падают на соседние (`outline` →
  `onSurface`, `surfaceContainer*` → `surface`); без явной прокидки рамка
  поля ввода рисовалась бы цветом `text.primary`, а диалог и шторка ложились
  бы на `surface.content` вместо `surface.overlay`. Роли §6 разложены по
  слотам `TextTheme`, чтобы `AppBar`, `ListTile` и кнопки брали шкалу
  системы, а не размеры Material;
- Figma Variables (`build/figma-variables.json`, собирается `npm run build`):
  четыре коллекции. `semantic` — с модами `brand × theme`, четыре комбинации
  переключаются одним селектором. `dimension`, `typography` и `motion` — без
  модов: отступы, радиусы, высоты строк, шкала текста и правила движения у
  всех брендов и тем одни и те же.

  **Два предупреждения.** Формат файла свой: нативного импорта переменных
  из JSON у Figma нет, а типовые плагины (Tokens Studio и подобные) ждут
  своей схемы. Чем именно файл попадает в Figma — плагином, скриптом через
  Figma API или руками, — не решено, и это первый вопрос перед началом
  работы дизайнера. Второе: четыре мода `бренд × тема` — потолок тарифов
  Professional и Organization; с Irissoft модов станет шесть, а это уже
  Enterprise. Проверить по тарифу. Стандартный обход — две коллекции: бренд
  как моды коллекции шкал, тема как моды `semantic` со ссылками на них. Он
  противоречит решению ниже не экспортировать примитивы, но Figma умеет
  скрывать коллекцию от публикации, и приглашение «красить из шкалы» этим
  снимается.

  В `typography` у каждой роли лежат и авторский вес, и вес, который реально
  нарисует код (`weight` и `weightRendered`): у Flutter `FontWeight` идёт
  шагом 100, поэтому `label` с весом 550 рендерится как 600, и дизайнер
  обязан видеть это там, где он рисует.

  Коллекции `component` нет, и это не упущение: §4.3 запрещает заводить этот
  слой на всякий случай — он появится, когда появится компонент, которому
  нужна отдельная ручка. Коллекции `primitive` нет по той же причине, по
  которой её не видят компоненты (§4.4): в Figma она была бы приглашением
  красить макет напрямую из шкалы.

**Направление синхронизации: JSON → Figma, не наоборот.** Если дизайнер правит
цвета в Figma напрямую, через месяц вернутся три расходящихся `colors.xml` в
новой обёртке.

Figma-файл содержит: переменные, компоненты с вариантами, и эталонные экраны —
по одному на раздел (карта, автопарк, отчёт, уведомления, видео, настройки) в
светлой и тёмной теме; для МТС — карта и отчёт, для проверки перекраски.

## 12. Что проверить перед стартом

- **Покрытие глифов Inter** для белорусского, украинского и греческого на
  реальных строках из `values-be`, `values-uk`, `values-el`. Проверка не
  проводилась.
- **Noto Sans Arabic** рядом с Inter: совпадение оптического размера и высоты
  строки в смешанной вёрстке.
- ~~**Контраст** всех пар `text.*` / `surface.*` по WCAG AA.~~ **Сделано и
  автоматизировано, но не для всех мыслимых пар:** гейт проверяет **21 пару**
  × 2 бренда × 2 темы на каждом `npm test` и на каждой сборке. Полный список
  перечислен в `design-system/tools/validate.js` (`CONTRAST_PAIRS`) — он и
  есть источник истины о покрытии, этот документ его только пересказывает.

  Из 16 комбинаций `text.*` × `surface.*` под порогом AA 4.5 стоят восемь:
  `text.primary` и `text.secondary` против `surface.content`, `surface.chrome`,
  `surface.selected` и `surface.overlay`. Не проверяются `text.disabled`
  (по определению не обязан проходить AA) и `text.onBrand` на нейтральных
  поверхностях (на них он не появляется — он живёт на `action.primary`, и
  эта пара проверяется отдельно). Остальные тринадцать пар — не
  `text.*`/`surface.*`: действие, все пять статусов, два трека карты и три
  структурных разделителя.

  **Разделители проверяются отдельно и по другой логике.** Теней в системе
  нет, поэтому поверхности разделяют ровно две вещи: ступень тона и волосяная
  граница. Их пороги (`border.hairline` на `surface.content` — 1.13, на
  `surface.chrome` — 1.04, `surface.chrome` на `surface.content` — 1.07) — не
  цель, а храповик: они равны сегодняшнему минимуму по брендам и темам,
  округлённому вниз до сотых, и существуют, чтобы шкалы нельзя было сплющить
  дальше незаметно. Достаточно ли этого разделения глазу — вопрос к дизайнеру,
  и ответ на него меняет нейтральные шкалы, а не пороги.

  **Самая узкая пара — `text.secondary` на `surface.chrome` в светлой теме
  МТС: 4.54 при пороге 4.5.** Запас 0.04. Это значит, что `neutral.500`
  (`#74706D`) и `neutral.50` (`#F7F6F5`) у МТС фактически связаны: сдвиг
  любого из них в сторону сближения ломает AA. Дизайнеру, который будет
  крутить тёплые нейтрали МТС, начинать нужно с этой пары. У Aurora та же
  пара идёт с запасом (4.79).
- **Альфа заливки геозон в тёмной теме.** Поставлена 35% против 25% в
  светлой (§5.5) — по рассуждению, а не по измерению на реальных тайлах.
  Проверяется вместе с треками.
- **Читаемость `map.track.*` на спутниковой подложке.** Синий трек на
  спутнике тонет — возможно, для спутникового режима нужен отдельный
  токен-переопределение.
- **Тёплые нейтрали МТС** (hue 28°) против их фирменного красного: тёплый
  серый рядом с красным может уходить в розовый.
- **Альфа `surface.scrim` в тёмной теме.** 60% против 40% в светлой (§5.4),
  по рассуждению, а не по измерению.
- **Палитра серий графика.** Сегодняшний `GraphFragment` красит до семи серий
  сырыми `Color.GREEN/BLUE/RED/CYAN/MAGENTA/YELLOW/GRAY`. В токенах
  категориальной палитры для данных нет, и `Chart` из §9.2 нечем красить,
  кроме `action.primary` и пяти статусов. Нужен `chart.series.*`, общий для
  брендов, как и статусы: это данные, а не оформление.
- **Подложки статусов.** Приложение сегодня красит ореол объекта и фон
  карточки 12-процентным тинтом статуса (`colorGreenLight` в
  `obj_icon_online.xml` и `fragment_eco_trip_details.xml`). `StatusBadge` с
  заливкой и белым текстом AA не пройдёт: 3.37 на `moving`, 3.20 на
  `offline`, 3.64 на `warning` в светлой теме. Либо `status.*Subtle` по
  образцу `action.subtle` с текстом цветом статуса, либо бейдж только
  контурный.
- **Ошибка формы против тревоги объекта.** `ColorScheme.error` сейчас берёт
  `status.alarm`, а на МТС это ещё и цвет primary-кнопки: ошибка валидации в
  логине, тревога объекта и кнопка одним цветом. Отдельный токен ошибки
  (`feedback.error`) или явно записанное решение «одним цветом».
- **Вес 550 у `label`.** Ничем не рисуется: код округляет до 600, и `label`
  выходит того же веса, что `section`. Либо записать в JSON то, что
  рендерится, и убрать `weightRendered`, либо положить переменный Inter и
  выдавать `FontVariation('wght', 550)` буквально.
- **Статусная точка на `surface.chrome`.** `status.offline` на хроме у Aurora
  светлой даёт 2.96, ниже порога 3.0. Если точки появляются в заголовках
  секций, пара нужна в гейте, и `offline` придётся двигать ещё раз.
- **Векторный знак МТС.** В `assets/brand/` лежит растр 240 px из сплэша
  (§10); для иконки приложения и крупных экранов нужен SVG от дизайнера.
  Вордмарк МТС тоже растр и не красится `currentColor`.

## Приложение Б. Что осталось незакрытым

Это нашло ревью, но чинить не стало — каждое решение меняет цвет, подобранный
человеком, и потому ждёт человека.

**У МТС трек с превышением скорости неотличим от обычного, и гейт этого не
видит.** `map.trackDefault` идёт от `action.primary`, `map.trackSpeeding` от
`status.alarm`. Для Aurora это синий против красного; для МТС `#D0050F` против
`#C7301F` в светлой теме и `#FF4D52` против `#F0554F` в тёмной, контраст между
ними **1.04** и **1.05**. Та же пара делает primary-кнопку и тревогу одним
цветом, то есть развод фирменного цвета и тревоги из §5.3 на МТС номинальный.
`CONTRAST_PAIRS` сравнивает цвет с поверхностью, а не два сигнала между собой,
поэтому все 84 проверки зелёные. Число измеряется в превью (`trackDistinction`
в `generate-preview.js`) и показано в разделе «Открыто», а демо-экран рисует
трек из двух отрезков, чтобы разницу можно было увидеть. Варианты: второй
признак у превышения кроме цвета (пунктир, ширина), трек по умолчанию не
брендовый, либо у МТС отдельная пара. После решения пару стоит добавить в гейт
как проверку различимости с собственным порогом.

**Подсветка выбранной строки стала слабее, и её никто не меряет.** Перенос
`surface.selected` на белую основу (§5.4) починил контраст текста на выделенной
строке, но одновременно сблизил саму подсветку с фоном: в светлой теме шаг
`surface.selected` против `surface.content` упал с 1.147 до **1.059** у Aurora и
с 1.161 до **1.074** у МТС. Это теперь самый слабый тональный шаг в светлых
темах — ниже порога 1.07, который мы же поставили на `surface.chrome`, и заметно
ниже 1.13 у волосяной границы. В системе без теней тон и есть единственный
разделитель, а шаг, который сообщает «вот эта строка выбрана», оказался
единственным неизмеряемым. Что делать: либо добавить пару
`surface.selected` / `surface.content` в `CONTRAST_PAIRS` с порогом по текущему
значению и оставить как есть, либо усилить подсветку — но второе меняет цвет,
подобранный дизайнером, и потому ждёт дизайнера.

**Порог 1.13 у волосяной границы держится на 0.00006.** Он выставлен ровно по
сегодняшнему значению Aurora, то есть фактически закрепляет `neutral.0` и
`neutral.100`. Как храповик это работает — шкалу нельзя случайно сплющить, — но
первый, кто тронет эти серые по другому поводу, получит `1.1299 < 1.13` и
прочтёт это как «я что-то сломал», а не как «ты ослабил разделитель».
Рекомендация ревьюера: опустить три пороги на сотую (1.12 / 1.03 / 1.06), а
сегодняшние точные значения вынести в тест отдельной таблицей-эталоном с
пометкой «менял шкалу намеренно — обнови строку и объясни в коммите».

**`assets/brand/` лежит вне публикуемого пакета, и это не обнаружится, пока
не появится компонент.** Потребитель подключает пакет как `path:
packages/aurora_design_system` (спек переноса, §4) и видит только это
поддерево; `assets/brand/aurora.svg`, `aurora-wordmark.svg`, `mts.png` и
`mts-wordmark.png` ему недоступны. Сегодня это ничего не ломает: Dart к
ассетам не обращается — в `tokens.g.dart` нет ни одной строки с путём к
файлу, знак и вордмарк использует только `tools/parity.js` (гейт на стороне
репозитория дизайн-системы) и сами файлы брендов. Но §9 обещает компонент,
показывающий знак и вордмарк, и в тот момент понадобятся сами файлы внутри
пакета, а спек переноса (§4) сам же утверждает, что путь пакета менять
после появления потребителей нельзя — `path:` в pubspec потребителей
сломается. Варианты: скопировать нужные файлы в
`packages/aurora_design_system/assets/brand/` при появлении компонента (два
экземпляра каждого файла, синхронизация — новый гейт), завести их как
Flutter-ассеты пакета с самого начала компонента (тот же дубль, но раньше),
либо вынести `assets/brand/` в отдельный маленький пакет, на который
подключение прописывается прямо в pubspec потребителя. Решать, когда дойдёт
очередь до §9.

**Подпись на подложке тревоги не дотягивает до AA в тёмной теме.** Роль
`status.alarmSubtle` пришла из макетов «Маршруты водителя», где бейдж
«Отменено» красится `status.alarm` на этой подложке. В светлой теме пара
даёт 4.64, в тёмной — **4.42**, то есть ниже 4.5. Соседние пары решены
иначе: у `moving` и `warning` в светлой теме подпись специально притемнена
(`#0B7A3C`, `#8A5A0F`) и обе проходят с запасом (4.76 и 5.06). У тревоги
такого притемнённого варианта нет — подпись равна самому статусу в обеих
темах. Поэтому пара `text.onAlarmSubtle` / `status.alarmSubtle` в
`CONTRAST_PAIRS` не внесена: заведомо красный гейт ломает работу всем, а
порог, подогнанный под 4.42, врёт. Варианты: завести
`status.onSubtle.alarm` для тёмной темы по образцу двух других (правка
цвета — за дизайнером), ослабить подложку, либо признать бейдж
нетекстовым элементом. После решения пару нужно внести в гейт.

**Макеты и токены разошлись на один разряд.** `surface.selected` в светлой
теме: `#F5F9FC` в `tokens/`, `#F5F8FC` в канвасах Claude Design. Значение в
токенах вычисляется как `mix({neutral.0}, {brand.600}, 0.04)`, в макетах
набрано руками. Пока расхождение живо, сверять макет с кодом автоматически
нельзя. Причина шире одного цвета: канвасы держат копии всех токенов
литералами (в «активной сессии» — 68 значений на четыре комбинации
бренд × тема), и там же живёт `font-size:12px`, роли для которого в системе
нет. Лечится подключением сгенерированного `build/design-system.css` в
проекты Claude Design вместо ручных копий.
